# 收藏后进入专辑：执行合同

仅用于已经通过完整专辑快照、Skill 归档保护核验和用户执行确认的逐条归档。浏览器授权、OCR 或普通“继续”不等于取消收藏授权。

## 两种真实入口

- 当前未收藏：在原笔记详情点击一次收藏，等待已收藏状态，立即点击本次出现的“加入专辑”，再选择已批准的目标。不先收藏全部、导航离开后再回来找入口。
- 当前已收藏且 `first_archive_pending`：先向用户说明需要取消一次再重新收藏。只有得到明确同意，才在同一笔记详情取消一次；看到未收藏状态后进入独立的 `await_recollect_ready` 阶段。必须同时满足：距离上次点击派发结束至少 500 毫秒，以及按钮及祖先节点的 `disabled`、`aria-disabled`、`aria-busy`、`inert` 和有效 `pointer-events:none` 限制已解除，才再收藏一次。看到已收藏状态后立即进入专辑选择器。悬停不是触发方式。

已由 Skill 登记保护的笔记始终零写入。未登记专辑成员与目标相同时只核验登记，不取消、不重收。目标不同的单专辑成员可在明确确认后使用上述流程；执行前必须完整读取实时成员并与批准的原位置精确一致，出现新的专辑关系、缺页或数量不符都停止，不能用旧快照强行操作。

## 必须说明的风险与同意

取消后重新收藏会改变收藏排序；中途失败可能留下未收藏或未归入状态。不得把这个动作隐瞒在“移动”一词里。

- 直接脚本：在展示映射、上限和上述风险并取得明确同意后，才可传 `--allow-recollect`。没有该参数时不取消收藏；收藏来源会在浏览器启动前拒绝，点赞来源若实时发现已收藏也在点击前拒绝。
- WorkBuddy：prepare 返回 `visible_assignment_contract`，必须把其中 `risk_notice` 与逐条计划一起展示给用户。它绑定在 approval digest 中；旧版未包含此合同的审批不能执行，须重新 prepare 和确认。用户不需要自己设置技术参数。

## 故障与核验

`scripts/xhs_album_assignment.js` 是新收藏和重收藏共用的正式页面状态流程。每次动作前检查账号、标签和 note id；不按标题搜索，不访问内部模块或私有接口。最多取消一次、收藏一次、点击目标一次，不自动重试。

任务下发前写入 `run_report.json.write_intents`。任何写入尝试后的入口缺失、超时、脚本状态丢失、安全验证或回读失败均记为状态不确定并停整批；有页面阶段证据时保留 `visible_ui_state`。不得猜测恢复成功，也不得在安全提示后自动补收藏。

按钮初始不可操作时，在取消/收藏前拒绝；取消后仍忙碌时，只观察状态，不向禁用控件派发合成点击。达到同一个总截止时间仍未就绪即停机，不重试。500 毫秒是下方已核实的客户端防连点规则，不是猜测性等待、随机间隔或安全验证绕过。`visible_ui_state.diagnostics` 保存单调时钟相对耗时、收藏图标状态、可见阻塞原因、点击时间及最早允许下次点击的时间，不保存 URL、请求正文或凭据。这些信号不能证明服务器请求已经结束，不能代替真实页面验收和最终成员回读。

## 已核实的客户端防连点规则

2026-09-13 对授权页面自然加载的公开前端资源做只读检查，定位到与可见控件 `data-v-5246910e` 对应的 `Collect` 组件。其点击处理器采用 500 毫秒、leading=true、trailing=false 的防连点设置；先通知图标更新，再等待请求完成。因此空心星标出现不代表可以立即再次点击，也不代表取消请求已完成。仅检查 DOM 禁用状态不足以解决这个问题。

源码证据：[小红书公开前端资源 index.0d8388d6.js](https://fe-static.xhscdn.com/formula-static/xhs-pc-web/public/resource/js/index.0d8388d6.js)，SHA256：`1246ae5237d97f588a4fb2e8fc8bc5a9bc2896e4a6a29a0ab636c149cdb279f6`。没有注入注册自定义 chunk、遍历运行时模块或调用私有接口；该源码也不随 Skill 分发或执行。

执行器用 `performance.now()` 计时，从点击派发结束起至少等待 500 毫秒，并继续执行状态、账号、控件检查；不修改或绕过网页自己的防连点逻辑。网页改版或状态不一致仍须停机，不得自动猜一个更长间隔反复试。

图标变黄仅代表可见收藏状态，不代表入专辑成功。必须看到目标的可见确认，再回读目标专辑精确增加该 ID；跨专辑还须原专辑精确减少该 ID。整批与最终完整快照通过之后才写新归档登记。

## 验收边界

`build_album_entry_preview_js` 是开发验收入口：它仍会改变收藏状态，必须对精确测试笔记取得授权；不是只读 dry-run。与正式执行共用状态流程，但找到目标专辑后立即清除观察器和定时器，返回 `preview_only=true, ok=false`，不点击专辑、不返回归档成功结果，也不生成归档登记。批量 execute 不调用此入口。

2026-09-13 在 WorkBuddy 专用 Chromium 实测确认了“未收藏 → 点击收藏 → 加入专辑 → 选择器显示”，没有提交专辑选择。之后对同一篇、另获明确同意的测试笔记运行生产流程的入口预览：观察到取消收藏及重新收藏各一次点击，但重新收藏未生效，在 `await_collected` 阶段超时；页面最后显示未收藏。程序已停止，零专辑选择、零重试，本次创建的浏览器进程全部关闭。仅凭这些证据不能确定是按钮短时锁定、异步状态未完成还是第二次程序点击未被页面接受，不得把推测写成已确认根因。

随后经用户另行授权，使用一次原生点击恢复了该测试笔记，并从收藏来源列表重新打开确认已收藏；专辑目录和声明数量未变化，零专辑选择。另一次只读检查取得上述公开源码证据。两个会话均关闭了全部自建浏览器进程。

已依据真实前端逻辑补上 500 毫秒防连点等待；对应的“图标提前更新且 DOM 不显示忙碌”离线用例先复现第二次点击被忽略，再通过修复。可见禁用检查与单调时钟用例也通过。

同日经用户要求重新实测，生产状态流程的预览分支成功完成取消一次、间隔约 601 毫秒后重新收藏一次、进入专辑选择器并显示精确目标。目标控件的 Playwright 原生 click trial 通过，没有提交点击；独立监听只记录 uncollect、collect、join 各一次，专辑选择零次。随后回到收藏列表按同一 note id 重新打开确认已收藏，前后专辑目录及声明数量一致；本次未观察到 300031，自建浏览器进程全部关闭。

该复验仅证明重收藏入口和目标可点击性，不代表实际归入、创建提交、完整成员回读或 WorkBuddy 宿主端到端已通过。没有因这次测试写入任何归档登记，也没有降低正式批量执行的完整快照与保护门禁。
