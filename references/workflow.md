# v2.0 执行工作流

这份流程把“读列表”“本地理解内容”和“移动笔记”分开。前两者可以生成分类方案；真正创建专辑或移动笔记前，必须再取得一次明确确认。

## 1. 启动与范围

先显示欢迎页，再让用户选启动方式：

1. **快速启动（按推荐设置）**：尽量少问问题；读取完成后，按真实的图文/视频比例给出推荐。
2. **完整启动（自己逐项设置）**：在需要时逐项选择 OCR、视频声音、视频画面、模型和分类规则。

选完启动方式才询问本次范围：

1. 收藏；
2. 点赞；
3. 我全都要（收藏与点赞合并去重）。

不要在读取列表之前猜测总数、图文比例或推荐分类。用户已在本轮明确给出启动方式或范围时，可以跳过对应问题。

## 2. OCR、浏览器和分段设置

两种启动方式都在读取列表前走完以下顺序：

1. 运行 `python3 scripts/check_environment.py --capability-preflight` 做本机只读检查。它只检查已配置的 OCR、声音、画面和宿主能力，不联网、不安装、不加载大模型，也不访问浏览器。
2. 显示“图文 OCR（推荐开启，以提高识别率）”。OCR 会逐张读取图文笔记封面和全部内页图片中的中英文可见文字；不安装仍可使用 Skill，但只能更多依赖标题、正文和标签。先复用已有 OCR；只有用户选择开启且检查发现缺失时，才展示本机的组件、实际大小和安装确认。详见 [图文 OCR 分类开关](image-ocr-classification.md)。
3. 取得**当前回合**对具体浏览器的授权。确认浏览器已经打开、已登录小红书、已经进入所选收藏或点赞页面，并已开启该浏览器所需的 JavaScript 能力。默认浏览器不能代替当前回合的授权；不要启动、连接或改用其他浏览器。
4. 让用户一次设置读取参数：每组条数（默认 `200`，最大只能为 `200`）和每组间暂停分钟数（默认 `3`）。同时确认“如果当次任务执行器已验证支持受控续组，本次读取会按此设置继续下一组；回复‘暂停’即可停下”。这是一份任务设置，不是平台公开的安全阈值，也不保证不会出现验证。

读取器只能在当次授权的页面接入被确认可用时工作。无法确认时，保留已保存内容并停下；不得切换到未授权或未经验证的浏览器路径。

## 3. 读取与本地分类

1. 读取时把每组结果和 manifest 先保存到本机；页面给出总数后，显示真实进度，例如 `已读取 200 / 1,000 条`。页面没有可靠总数时，明确显示“总数未知”，不要编造预计值。
2. 只有用户已一次确认自动继续、当次任务执行器已验证支持受控续组时，才按其每组条数和暂停分钟数继续读取剩余组；用户说“暂停”、浏览器状态异常或出现安全验证时立即停止。否则保留旧的 `--capture-mode passive` 单组、手动继续路径。
3. 读取完成后，合并本地分段并按 note id 去重。此时才根据真实数据展示“图文 X 条 / 视频 Y 条 / 未确认 Z 条”，再决定后续内容理解方式。
4. 快速启动根据真实分布给出推荐：图文多时优先 OCR；视频占比明显时询问是否加用视频实际内容识别。完整启动逐项询问视频声音、视频画面、可复用模型或其他 Agent，以及分类规则。视频功能的细节见 [根据视频实际内容分类](video-content-classification.md)。
5. 图文 OCR、视频转写、视频画面分析、去重和分类都尽量在本机完成。视频声音、字幕和画面证据只用于生成简短分类 memo 与证据数据；不是移动操作，也不是另一份长报告。
6. 输出**分类方案预览**：默认只显示拟用专辑名称、每个专辑的条数、待人工复核数和失败数，不展示每个专辑内的条目。只有用户明确要求，才展开某个或全部专辑的条目供审阅。

图文 OCR 必须使用详情确认的完整图片集合；视频内容分类失败或证据不足时，目标专辑留空并进入人工复核，不能退回按简介猜测。详细输入输出字段见 [输入输出契约](io-contract.md)。

## 4. 创建专辑与移动

1. 先让用户确认分类方案、目标专辑、待新建专辑和审阅范围。
2. 用完整的专辑成员关系生成 dry-run；已在目标专辑的条目排除，多来源或来源不明的条目不进入执行。
3. 只有用户再次明确同意后，才运行 `scripts/run_reassign_batch.py --execute`。真实移动仍受每次明确范围和页面核验约束；不要把“读取可自动续组”误解成“移动可自动执行”。
4. 执行后用只读核验确认成员关系，保留 `run_report.json` 与失败队列。页面状态不确定、安全验证或登录失效时立即停写。

## 5. 验证与恢复

出现安全验证、异常访问提示、登录页、页面绑定丢失或写入状态不确定时：保存已完成分段和停止原因，停止所有小红书访问与写入，并提示用户在小红书当前页面完成处理、回到列表页后回复“继续整理”。

用户回复“继续整理”后，只检查当前已授权页面是否恢复可用；不重读已保存分段、不自动重试触发问题的请求，也不在这次恢复检查中继续详情读取、视频分析或移动。检查通过后，才按原有未完成队列和已确认设置恢复。详见 [失败恢复与续跑](recovery-and-resume.md)。

## 6. 每周整理任务

第一次完整整理结束后，询问是否设置每周固定时间。若用户开启，再询问星期与时间，并保存本次的范围、分段设置、OCR/视频选择、分类规则和审阅方式。

每周任务只读取新出现的内容并先生成新的分类方案；不自动创建专辑、不自动移动笔记。到时间后仍需要用户在**当次**确认浏览器可用和登录正常，才可以开始读取；不能拿一周前的浏览器授权或登录态继续操作。

## 关键边界

- 浏览器只能由用户在当前回合明确授权并显式指定；`--browser auto` 不执行真实浏览器操作。
- `200` 是本 Skill 的单组上限，不是平台公开阈值，暂停也不应被描述为规避验证或模仿真人。
- 不读取、不记录、不外传 cookie、token、xsec 或完整签名 URL。
- 分类方案预览、dry-run、OCR、转写和视觉分析都不等于移动授权。
