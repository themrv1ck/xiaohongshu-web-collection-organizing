# v2.0 新用户启动与整理流程

本文件是 v2.0 的唯一新用户入口。`SKILL.md`、README 和其他参考文件如有旧版流程描述，以本文件为准。

## 先说清楚边界

- 读取、分类和移动是三件不同的事。先读取，再在本地生成分类方案，最后单独确认是否创建专辑或移动笔记。
- 浏览器只能使用用户在**当前这次整理**明确指定、已经登录并已经打开小红书页面的浏览器；不得复用一周前的浏览器许可。
- 出现登录页、安全验证、异常访问、页面绑定丢失或写入状态不确定时，立即保存状态并停止；不得重试、刷新、绕过验证或继续移动。
- 用户设置的分段数量和暂停时间用于控制本次工作节奏，不保证平台不会要求验证，也不用于伪装成人。

> - 视频可按声音、字幕和画面内容分类；

>

> 1. 收藏
> 2. 点赞

“我全都要”时，收藏与点赞各自读取、本地按 note id 去重；同一笔记保留两个来源。

## 两种启动方式共同的前半段

### 1. OCR 在读取前询问

无论快速还是完整启动，都先显示：

> **图文 OCR（推荐开启，以提高识别率）**
>
> OCR 就是把图片中的中英文文字读出来。它会读取图文笔记封面和全部内页图片，而不只看封面。
>
> 例如标题只写“建议收藏”，内页却写着“上海两天一夜路线、餐厅和交通方式”。开启后可以把它归到“旅行 / 上海攻略”，而不是只凭标题猜。
>
> OCR 只能读图片里的文字，不能理解没有文字的纯画面。它通常能覆盖大约 60% 的图文整理场景，所以推荐安装；不安装也能继续用 Skill，只是分类可能不够准确。
>
> 1. 开启 OCR
> 2. 暂不开启

用户选择开启后，先运行只读检查：

```bash
python3 scripts/check_environment.py --capability-preflight
python3 scripts/check_environment.py --ocr
```

- 已有中英文 OCR：直接复用，不安装。
- 缺失 OCR：先显示当前系统实际要安装的组件、预计下载量和磁盘占用，再询问是否安装。
- macOS：优先使用系统 Vision，通常没有额外 OCR 模型下载；若缺少 Command Line Tools，以系统安装窗口显示的实际体积为准。
- Windows：默认 Tesseract + `chi_sim` 和 `eng`，通常几十到数百 MB；默认位置 `C:\Program Files\Tesseract-OCR\`。此行只显示给 Windows 用户。
- 用户选择不开启：显式用 `--skip-ocr` 分类，不能悄悄复用已发现的 OCR。

### 2. 当前浏览器授权与页面检查

OCR 选择完成后，询问：

> 请确认已经打开一个已登录小红书的浏览器，并停在本次要整理的收藏或点赞页面。
>
> 此页面需要允许 Skill 运行必要的 JavaScript，用于读取当前列表；不会在未确认前创建专辑或移动笔记。
>
> 1. 使用默认浏览器
> 2. 选择另一个已登录浏览器

只在用户当前回复确认后，检查该浏览器、登录状态、目标页面和 JavaScript 能力。未登录时让用户自行登录；不后台轮询，也不自动换浏览器。

### 3. 一次设置分段读取

在第一次读取前只问一次：

> 这次每组读取多少条、每组之间暂停多久？
>
> 默认：每组最多 200 条，暂停 3 分钟。
>
> 你可以回复“默认”，或回复“每组 <数量> 条，暂停 <分钟> 分钟”。每组最多 200 条。

保存为本次配置：

```bash
python3 scripts/onboarding_config.py run_config.json \
  --startup-mode <quick|complete> --source <collection|liked|all> \
  --ocr <enabled|disabled> --batch-size <1-200> --pause-minutes <正整数>
```

用户一次确认后，任务执行器可按该设置安排下一组；在用户没有回复“暂停”时不再重复询问。每一组独立保存进度和 manifest。`extract_visible_items.py --capture-mode segmented` 只负责校验、读取并落盘当前一组；它不会自行滚动、刷新、打开 URL 或续段，下一组只能由已经获得该一次性授权的任务执行器发起。第一次页面读取后，若页面可提供总数，显示“已读取 <n>/<总数>，预计 <段数> 段”；页面未提供总数时，只显示已读取数量，不能猜总量。

被动手动模式仍保留给希望自己逐段确认的用户；它不滚动也不自动续段。受控分段模式必须显式带上批次设置与一次性继续授权，不能把旧的被动模式改成自动模式。

## 读取完成后的分流

全部所选列表读取完成后，先给真实统计，而不是事先预测：

> 已读取完成：图文 <数量> 条，视频 <数量> 条，待确认 <数量> 条。
>
> 接下来会按真实内容生成分类方案；尚未创建专辑，也没有移动任何笔记。

### 快速启动

快速启动按已选 OCR 和真实内容分布给出推荐：

- 图文不少于视频：推荐使用 OCR（如果已开启）+ 标题、正文、标签和作者。
- 视频多于图文：额外询问是否启用视频实际内容识别。
- 类型待确认较多：先标为人工复核，不把不确定条目按简介猜进专辑。

视频提示必须在读取统计后出现，并给例子：

> 视频标题写“太香了”，讲解实际在教番茄炒蛋；读取声音或字幕后可以归到“做饭 / 菜谱”。
>
> 如果视频没有说话，只在演示整理衣柜，声音无法判断；读取完整时轴画面后才可以归到“收纳整理”。

选项：

1. 耳朵和眼睛都要（通过字幕、视频语音和完整时轴画面识别内容）
2. 先检查我是否已有类似功能的 AI 或模型
3. 不开启

### 完整启动

完整启动在真实分布后逐项确认：

1. 是否处理视频声音/字幕；
2. 是否处理视频完整时轴真实画面；
3. 使用已有宿主 Agent、已有本地模型，还是安装缺失组件；
4. 使用推荐分类规则还是用户自定义的专辑规则；
5. 是否保留已有专辑内容不动。

完整启动可以在此处单独选择“只分析声音”；快速启动不额外增加这个技术选项，避免把第一次使用者带进不必要的设置。

不得把画面识别固定为 Codex CLI。可用 provider 包括已有宿主 Agent/API 的 `command` 适配器、`mimo-vl-mlx`，或用户明确提供的其他视觉能力。MiMo-VL 只负责画面；字幕或语音文字由平台字幕或 ASR 提供。

缺失组件必须先检查再安装。参考体积：`MiMo-V2.5-ASR-MLX` 约 6.6 GB；`MiMo-VL-7B-RL-2508` 约 16.6 GB。仅在用户选择对应能力且确认安装后安装。

## 分类方案预览、审阅与移动

分类在本地完成，得到 `classification.json`。这里的“本地”是指先在电脑上根据已经读取到的文本、OCR 和视频 memo 计算方案，尚未改变小红书内容。

先展示**分类方案预览**：建议专辑名、每个专辑的数量、低置信度和待确认数量。默认不展开专辑内的具体笔记，以免一次显示过多内容；随后问：

> 是否展开查看每个专辑里的条目？
>
> 1. 展开查看
> 2. 只看数量，继续下一步

只有用户确认专辑名称、已有专辑处理方式和移动方案后，才允许创建专辑或执行 `run_reassign_batch.py --execute`。先执行 dry-run，实际写入时每条独立核验；安全状态或写入状态不确定时立即停止。

## 安全验证后的恢复

遇到安全验证、异常访问、登录提示、页面绑定失效或状态不确定时：

1. 立即保存已读取分段、分类进度和 `xhs_safety_state.json`；不继续读取、详情访问、视频分析或移动。
2. 告知用户：请先在小红书里完成验证并回到目标列表页，然后回复“继续整理”。
3. 收到“继续整理”后，只检查当前页面与保存状态是否一致；不重新读取已经保存的部分。
4. 检查通过后按原来的分段方案继续；检查不通过则说明具体原因并等待用户处理。

内部实现不得绕过 `security_halted`：旧状态不能直接 `--resume`，恢复必须建立新的活动会话，并引用已保存、不可改写的已完成段。

## 每周整理任务

第一次完整整理结束后，显示：

> 本次整理已完成。
>
> 是否开启每周固定时间的小红书整理任务？
>
> 开启后，Skill 会复用本次的整理范围、每组读取数量与暂停时间、OCR、视频识别、分类设置和审阅方式。
>
> 每周只整理新出现的内容，并先生成新的分类方案；不会自动创建专辑或移动笔记。
>
> 1. 开启每周整理
> 2. 暂不开启

若用户开启，再询问星期与时间，写入 `run_config.json` 的 `weekly_task`。到点时任务只生成待办和本次配置；需要用户在当次确认一个已登录浏览器后，才能读取新内容。任何自动任务都不得沿用旧浏览器授权，也不得自动移动笔记。

每周读取完成后，先用 `weekly_delta.py` 从保存的 note id 基线中筛出新内容。默认只写预览；只有新的 `classification.json` 覆盖每一条新笔记后，才提交新的基线，因此分类失败或中断不会把未处理条目错误地标为已完成：

```bash
python3 scripts/weekly_delta.py visible_items.json weekly_delta.json \
  --baseline weekly_processed_note_ids.json

python3 scripts/weekly_delta.py visible_items.json weekly_delta.json \
  --baseline weekly_processed_note_ids.json \
  --commit-after-plan classification.json
```
