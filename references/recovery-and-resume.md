# 失败恢复与续跑

## 触发安全停机时怎么做

同一次整理的所有小红书访问都必须共用一份 `xhs_safety_state.json`。它只记录运行状态和停止原因，不保存 cookie、token 或完整签名 URL。

出现安全验证、异常访问提示、登录页、浏览器页面绑定丢失、浏览器状态桥消失或写入状态不确定时：

1. 立即把已完成分段、manifest、分类方案和停止原因保存到本机；
2. 将状态写为 `security_halted`，停止采集、详情补齐、视频访问、移动和只读核验；
3. 不刷新页面、不点击验证、不切换 UA/代理/IP、不模拟真人行为，也不重试触发问题的请求；
4. 告知用户：请在小红书当前页面完成必要处理并回到列表页，然后回复“继续整理”。

`--resume` 不能清除或绕过 `security_halted`。`200` 也不是平台公开阈值，分段暂停不能保证不会出现验证。

## 用户回复“继续整理”后的恢复顺序

用户完成平台内处理并在当前对话回复“继续整理”后：

1. 只对用户在**当前回合**授权的浏览器做一次当前状态检查；确认它已打开、已登录、仍在目标列表页且 JavaScript 接入可用。
2. 为新的浏览器访问创建新的安全状态记录，保留旧状态文件作为审计记录。
3. 不重读已保存的列表分段，不自动重试先前失败的详情请求；恢复检查本身不继续详情读取、视频分析或移动。
4. 检查通过后，按原先已确认的范围、每组条数、暂停分钟数和未完成队列继续。检查不通过则停下并显示当前需要用户处理的状态。

恢复的目标是保留进度，不是绕过平台提示。不得因为用户说“继续整理”就更换浏览器、加快操作或启动额外重试。

## 分段规则

- 读取前由用户一次设置每组条数（默认 `200`，最大 `200`）和组间暂停分钟数（默认 `3`）。
- 用户已一次确认自动继续、且当次任务执行器已验证支持受控续组时，任务可在已确认的页面接入持续可用、没有安全状态且用户没有说“暂停”的条件下，按保存设置请求下一组；每组都先落盘。
- `--capture-mode passive` 仍保留为单组、手动继续的兼容路径；没有一次自动继续确认、执行器未验证续组能力或无法确认浏览器接入时，必须使用该路径。
- 图文详情、视频读取和真实移动都仍需要其各自的明确范围与授权；不能因为列表读取可续组而自动扩大到写入操作。
- 分类、去重和专辑规划尽量只在本机完成；真正移动只按用户审阅后的本地分类结果执行。

## 本地结果复用

- `image_items.json` 只有在详情确认图文、`image_enrichment_status=ok`、`image_list_source=mobile_ssr_note_data.imageList`、`image_urls_complete=true` 且图片集合完整时才可复用。
- `ocr_results.json` 只有条目 `status=ok`、完整性计数一致、`image_set_sha256` 与当前图片集合一致，且 `ocr_run_fingerprint` 与本次运行一致时才可复用。
- 视频转写、画面分析和移动同样只复用完整成功项；输入变化、安全停机或证据不完整时，保留真实失败状态，不作猜测性补救。
- `retry_queue.json` 中 `retry_eligible=false` 的项需要用户处理后，在新的会话状态下重新开始；普通失败也先人工复核，再明确开始新的会话。

## 每周任务

每周任务只能复用用户保存的范围、读取设置、OCR/视频选择、分类规则与审阅方式。到约定时间后，它只能准备“本周新内容”的分类方案任务；不会自动创建专辑或移动笔记，也不能复用上周的浏览器授权。用户在当次确认浏览器已登录且可用后，才可以开始新的读取会话。
